# Vex 云物联 后台管理端 UI 交互设计

> **版本**: v1.0 草案
> **面向**: 前端开发 / 产品 / 后端 (用于补齐缺失接口)
> **技术栈**: React 18 + TypeScript + Vite + HeroUI (https://heroui.com/)
> **关联**: [接口清单基于 `service/src/main/java/com/vex/iot/app/http`]

---

## 一、设计原则

- **清晰可读**: 后台类项目优先信息密度与可扫读性,避免花哨动效。
- **角色驱动**: 按钮/路由显隐按 `roles.includes('ADMIN')` 渲染,后端 `@PreAuthorize` 二次校验。
- **统一查询**: 所有列表使用 `POST /xxx/query` + `POST /xxx/count`,基于 `QueriesPageRequest`。
- **实时优先**: 实时点位与告警通过 `/api/sse/stream` 单连接推送,UI 就地更新,避免轮询。
- **失败兜底**: SSE 断线 5s 自动重连;HTTP 401 → 静默 refresh → 失败 → 回登录。

```
┌──────────────────────────────────────────────────────────────────┐
│ [名称 🔍] [编码 🔍] [在线状态 ▾] [启用 ▾] [分组 ▾] [+ 新增]      │
├──────────────────────────────────────────────────────────────────┤
│ ☐  设备名称    编码      分组    在线  启用  最近心跳       操作   │
│ ☐  1号车间PLC  DEV-001  车间A   🟢    ✓    12:01:00    [详情][编辑]│
│ ☐  2号车间PLC  DEV-002  车间A   🔴    ✓    11:48:11    [详情][编辑]│
├──────────────────────────────────────────────────────────────────┤

└──────────────────────────────────────────────────────────────────┘
```

**交互流程**:

```
[进入] POST query+count → 渲染
[筛选变化] 防抖 300ms → 重新 query+count
[分页/排序] → 重新 query

[新增] Drawer 右抽屉
  ├─ 字段: 名称* 编码* 分组 描述 MQTT凭证 模板(下拉)
  └─ POST /api/devices
       ├─ 成功 → 提示"是否从模板初始化点位?"
       │        ├ 是 → POST /devices/{id}/points/init-from-template
       │        └ 否 → 关闭 + 刷新
       └─ 失败 → 字段红字

[编辑] Drawer 同上 → PUT /api/devices/{id}
[删除] Popconfirm → DELETE /api/devices/{id}
[批量删除] 多选 → Popconfirm → 循环 DELETE
[详情] → 跳转 /devices/{id}
```

## 四、跨页面交互约定

| 场景 | 约定 |
|---|---|
| 鉴权 | 路由守卫:无 token → /login;401 → 静默 refresh → 失败 → /login |
| SSE | 单连接,断线 5s 自动重连;按 `id` 隔离事件 |
| 列表查询 | 入参 `QueriesPageRequest { conditions, orders, page, size }`;封装 `useQuery` hook |
| 权限 | UI 层按 `roles` 控制按钮;后端 `@PreAuthorize` 二次校验 |
| Toast | 成功 1.5s 自动消失;失败/告警长驻 |
| 时间 | ISO8601 提交;前端 Asia/Shanghai 渲染 |
| 空状态 | HeroUI `<EmptyState>` + 主操作按钮 |
| 加载 | 表格 skeleton;按钮 `isLoading` 防重 |
| 表单 | HeroUI `Form` + zod 校验;字段错误内联提示 |
| 抽屉/Drawer | 表单类用 Drawer;详情类用 Modal 或详情页 |

## 五、SSE 事件约定 (前端订阅)

| 事件类型 | 触发源 | UI 反应 |
|---|---|---|
| `alarm.event` | 告警触发/确认 | 角标 +1,Notification,事件表头插入 |
| `point.realtime` | MQTT 上行 | 实时点位就地更新,时间戳闪烁 |
| `device.online` | 设备上下线 | 设备列表/概览卡片在线状态切换 |
| `notify.sent` | 通知发送结果 | 通知中心 toast(若启用) |

> 实际事件名以后端 `SsePusher` 实现为准,本节为前端约定草案。

## 七、前端技术决策

- **UI 库**: HeroUI (基于 Tailwind + React Aria,无障碍与暗色友好)
- **状态**: TanStack Query (server state) + Zustand (client state)
- **路由**: React Router v6
- **HTTP**: Axios + 拦截器统一处理 `Response<T>` 与 401 refresh
- **图表**: Recharts (与 HeroUI 风格兼容)
- **表单**: HeroUI `Form` + `zod`
- **图标**: @heroicons/react
- **SSE**: EventSource + 自定义 hook `useEventStream`
- **目录约定**:
  ```
  src/
    api/        # 按模块的 axios 调用
    pages/      # 路由级页面
    components/ # 通用组件 (Table/Form/Drawer/...)
    hooks/      # useQuery/useEventStream/...
    stores/     # zustand
    lib/        # http/format/perm
  ```
