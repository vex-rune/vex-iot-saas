# 软件概要设计文档

> 本概要设计仅包含**网络架构、系统模块架构**，不涉及接口设计、数据库模型、代码细节。
> 与 [`README.md`](../../README.md) 和 [产品需求文档](./01-产品需求文档.md) 保持一致；点表模板约定见 §3.4。

## 1. 总体设计说明

本系统采用**前后端分离架构**，后端为 SpringBoot 单体架构，部署双实例配合 Nginx 实现负载均衡；设备通信基于 MQTT 协议，业务数据存储采用 MongoDB，时序高频数据按需引入时序库（选型待定）；集成短信、微信消息推送能力；点表配置通过 `resources/templates/point-table/` 下的 JSON 模板按设备类型预置，降低现场配置成本。

整体架构：**轻量化、高可用、易维护、可配置**。

## 2. 网络架构设计

### 2.1 整体网络拓扑结构

整体网络分为五层，层级隔离、职责清晰：

```
┌─────────────────────────────────────────────────────────────┐
│                     客户端访问层                               │
│              浏览器 ← React 前端页面                          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTPS 443
┌──────────────────────────▼──────────────────────────────────┐
│                     负载均衡层                                 │
│              Nginx 反向代理 + 负载均衡                        │
│         （静态前端资源 + API 请求分发）                        │
└──────────────────────────┬──────────────────────────────────┘
                           │ VPC 内网 HTTP
        ┌──────────────────┴──────────────────┐
        │                                     │
┌───────▼────────┐                  ┌────────▼─────────┐
│  SpringBoot 实例1 │                  │  SpringBoot 实例2  │
│   （业务服务层）   │                  │   （业务服务层）    │
│  无状态 / 代码一致 │                  │  无状态 / 代码一致  │
└───────┬────────┘                  └────────┬─────────┘
        │                                     │
        └──────────────────┬──────────────────┘
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
┌───────▼────────┐  ┌──────▼───────┐  ┌──────▼────────┐
│  EMQX MQTT     │  │   MongoDB    │  │  第三方服务层   │
│  （设备通信层）  │  │  （数据存储） │  │ 短信 / 微信通知 │
└───────┬────────┘  └──────────────┘  └───────────────┘
        │ MQTT 1883/8883
┌───────▼────────┐
│  PLC / 网关设备 │
│  （现场设备层）  │
└─────────────────┘
```

### 2.2 各层职责说明

| 层级 | 组件 | 职责 |
|------|------|------|
| 客户端访问层 | 浏览器 + React 前端 | 用户通过浏览器访问前端页面，发起所有业务操作请求 |
| 负载均衡层 | Nginx | 反向代理与负载均衡，统一分发前端请求至双 SpringBoot 服务实例，托管静态前端资源，部署 HTTPS 证书 |
| 业务服务层 | SpringBoot × 2 | 两台完全一致的单体服务实例，无状态部署，共享 MongoDB 数据、共享 MQTT 通信服务，承载全部业务逻辑 |
| 设备通信层 | EMQX MQTT Broker | 工业网关、PLC 设备与平台服务的双向数据通信（设备上报数据、平台下发控制指令） |
| 第三方服务层 | 短信 API + 微信 API | 对接外部短信服务、微信消息服务，实现报警通知推送 |

### 2.3 核心网络通信规则

| 通信链路 | 协议 | 说明 |
|---------|------|------|
| 前端页面 ↔ Nginx ↔ SpringBoot | HTTP/HTTPS | 承载所有业务查询、配置、控制请求 |
| PLC/网关设备 ↔ EMQX ↔ SpringBoot | MQTT | 设备数据上报、平台控制指令下发，双向通信 |
| SpringBoot ↔ 第三方短信/微信接口 | HTTPS | 外网消息推送，报警通知 |
| SpringBoot ↔ MongoDB | 内网 TCP | 业务数据读写，全部走 VPC 内网 |

### 2.4 高可用设计（双实例负载均衡）

| 设计点 | 说明 |
|--------|------|
| 服务无状态化 | 两个 SpringBoot 实例代码、配置完全一致，不存储本地会话，所有数据持久化至 MongoDB |
| 请求负载分摊 | Nginx 轮询分发用户请求，避免单实例压力过载 |
| 故障自动容错 | 单实例宕机时，Nginx 自动剔除故障节点，所有请求自动转发至正常实例，保障系统不中断 |
| MQTT 消费去重 | 采用 MQTT 共享订阅机制（`$share/group/topic`），避免双实例重复消费设备消息、重复触发报警与数据更新 |
| 认证无状态 | JWT Token 认证，两个实例均可独立校验，无需共享会话 |
| 模板一致 | 点表 JSON 模板打包在 JAR 内 `resources/templates/point-table/`，两个实例加载同一份模板，无需外部共享存储 |

## 3. 系统模块架构设计

系统整体采用模块化分层设计，按职责划分为**基础支撑模块**和**核心业务模块**，模块间低耦合、高内聚，便于维护与迭代。

### 3.1 模块总览

```
┌────────────────────────────────────────────────────────────────────────┐
│                          核心业务模块（上层）                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│  │ 设备管理  │ │ 点表管理  │ │ 数据展示  │ │ 点位控制  │ │ 通知人管理│ │ 报警管理  │ │ 报表导出  │ │ 系统配置  │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
└──────────────────────────────┬─────────────────────────────────────────┘
                               │ 依赖调用
┌──────────────────────────────▼─────────────────────────────────────────┐
│                          基础支撑模块（底层）                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│  │ 权限管控  │ │ MQTT通信 │ │ 消息通知  │ │ 数据持久  │ │ 通用计算  │ │ 模板管理  │ │ 审计日志  │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
└────────────────────────────────────────────────────────────────────────┘
```

> 与旧版相比，**新增"数据展示"、"报表导出"、"系统配置"、"模板管理"、"审计日志"** 五个模块，对齐 PRD §2 的完整功能域。

### 3.2 基础支撑模块（公共底层能力）

#### 3.2.1 权限管控模块

系统底层核心权限模块，基于角色实现权限分级管控。

- 拦截所有业务请求，校验用户角色权限
- 实现超级管理员 / 管理员 / 操作人员 / 访客的功能隔离，杜绝越权操作
- 基于 JWT 无状态认证，Spring Security 框架实现
- 细粒度控制：菜单级 + 接口级 + 业务级三层校验（如只读点位拦截控制、租户数据隔离）
- 支持多租户：租户维度数据过滤贯穿所有业务模块

#### 3.2.2 MQTT 通信模块

负责服务与 EMQX 中间件的长连接管理。

- 设备数据订阅接收（共享订阅，双实例负载消费）
- 远程控制指令发布下发
- 内置断线重连、消息去重、通信异常处理能力
- 设备上报消息解析 → 点表匹配 → 公式计算 → 数据更新 → 报警检测的完整链路
- 主题规划：上行 / 下行 / 心跳 / 报警主题分层命名，ACL 三级管控

#### 3.2.3 消息通知模块

统一封装第三方短信、微信通知能力。

- 提供通用的消息推送接口
- 接收报警模块 / 系统模块推送的通知任务
- 完成多渠道（短信 + 微信）消息下发
- 支持通知失败重试，通知结果记录可追溯
- 支持定时报表推送

#### 3.2.4 数据持久模块

基于 MongoDB 实现所有业务数据的存储、查询、更新。

- 支撑所有业务模块的数据读写需求
- 保障数据一致性与可靠性
- 点位历史数据按月分集合 + TTL 自动过期 + 定时归档 OSS
- 业务数据与时序数据分类存储
- 数据库版本管理（Flyway / Liquibase 等）

#### 3.2.5 通用计算模块

内置点位数据公式计算能力。

- 设备原始数据的正向展示转换（PLC 原始值 → 页面显示值）
- 平台控制参数的反向指令转换（页面输入值 → PLC 写入值）
- 支持 `round()`、四则运算等白名单函数，`$a` 作为变量占位符
- 公式引擎安全：禁止执行任意脚本，仅支持白名单表达式，防止注入攻击

#### 3.2.6 模板管理模块

点表模板的加载、缓存、版本管理能力。

- 启动时加载 `resources/templates/point-table/` 下的 JSON 模板到内存
- 提供模板查询接口，供前端"按设备类型选择模板"使用
- 模板变更随版本发布，与代码一同走 CI/CD，无需运行时热加载（保持简单）
- 详见 §3.4 点表模板约定。

#### 3.2.7 审计日志模块

横切所有写操作的全量记录能力。

- 记录配置变更、控制下发、报警确认、用户操作等关键事件
- 操作人、操作时间、操作对象、操作前后值全量留痕
- 支持按用户 / 时间 / 对象类型查询

### 3.3 核心业务模块（上层业务功能）

#### 3.3.1 设备管理模块

负责所有工业设备、网关的全生命周期管理。

- 设备接入配置（MQTT ClientID、上报 Topic、下发 Topic）
- 在线状态监测（在线 / 离线 + 上下线事件 + 最近心跳）
- 设备信息维护（名称、编号、描述、所属网关、启用 / 禁用）
- 设备分组与标签、网关 → 设备拓扑展示
- 为点位配置、数据采集、报警监测提供设备基础载体

#### 3.3.2 点表管理模块

负责 PLC 设备点位参数的统一配置管理。

- 提供**点表模板**（详见 §3.4），按设备类型预置点位列表，用户在模板基础上按设备微调
- 定义点位寄存器规则（寄存器类型、地址偏移、位偏移）
- 数据类型配置（BIT、FLOAT4、UINT16 等）
- 读写权限配置（只读 / 可读可写）
- 转换公式配置（正向公式、反向公式）
- 批量导入 / 导出能力
- 是设备数据采集与远程控制的核心配置模块

#### 3.3.3 数据展示模块

负责设备点位数据的可视化。

- 实时数据展示（所有点位最新值，含原始值 + 公式转换后展示值）
- 历史数据查询（按设备 / 点位 / 时间范围）
- 可视化看板（曲线 / 仪表盘 / 地图），支持自定义布局
- 数据筛选：时间范围、聚合方式（均值 / 最大 / 最小）、死区过滤

#### 3.3.4 点位控制模块

处理远程控制请求，配套权限保护。

- 校验点位操作权限，仅"可读可写"点位允许控制
- 开关量远程置位 / 复位
- 数值量远程修改下发
- 下发指令经反向公式转换后通过 MQTT 发布至设备
- 控制操作全量审计日志记录

#### 3.3.5 通知人管理模块

维护报警接收人员档案。

- 通知人信息维护（姓名、手机号、微信 OpenID、部门）
- 短信通知开关、微信通知开关独立配置
- 通知人分组，便于报警规则批量关联

#### 3.3.6 报警管理模块

包含报警规则配置、实时异常监测、报警事件记录、故障恢复识别、消息推送触发能力。

- 报警规则配置（阈值条件 gt / lt / eq / 区间 / 表达式、持续时间、级别）
- 实时监听点位数据，异常自动触发报警，重复抑制
- 故障恢复自动识别与记录
- 报警确认 + 超时升级
- 报警历史记录 + 统计图表
- 触发消息通知（调用消息通知模块，推送至关联通知人）

#### 3.3.7 报表导出模块

负责报表生成、导出与分发。

- 导出格式：Excel、PDF
- 报表模板管理，支持自定义字段、样式
- 定时报表：按日 / 周 / 月自动生成并推送
- 导出历史记录，可重新下载

#### 3.3.8 系统配置模块

平台级配置管理。

- 字典管理（通用字典维护）
- 单位管理（物理量单位、量纲转换）
- 协议字典（Modbus 寄存器、数据类型、公式函数）
- 系统参数（平台名称、Logo、登录页等）

### 3.4 点表模板约定

> 点表模板是本系统降低现场配置成本、提升一致性的关键约定，单独列出。

#### 3.4.1 模板位置

```
src/main/resources/templates/point-table/
├── plc-type-a.json        # PLC 类型 A
├── plc-type-b.json        # PLC 类型 B
└── plc-type-c.json        # PLC 类型 C
```

> 当前**预置 3 套 PLC 模板**，对应现场 3 类 PLC 设备。后续若新增设备类型，按相同目录追加 JSON 文件即可。
> 模板随 JAR 一同发布，升级靠版本发布；不提供运行时热加载，保持简单可控。

#### 3.4.2 模板格式（JSON）

每份模板描述一个完整的点表预置集合，核心字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| `templateCode` | 模板编码，全局唯一 | `plc-type-a` |
| `templateName` | 模板名称，用于前端展示 | `PLC-A 标准点表` |
| `deviceType` | 适用设备类型 | `PLC-A` |
| `version` | 模板版本号 | `1.0.0` |
| `description` | 模板说明 | `适用于 XXX 系列 PLC` |
| `points` | 点位列表 | 见下 |

`points[]` 中每个点位的字段：

| 字段 | 说明 |
|------|------|
| `pointCode` | 点位编码 |
| `pointName` | 点位名称（页面显示） |
| `registerType` | 寄存器类型（M / Q / VD / VW 等） |
| `addressOffset` | 地址偏移 |
| `bitOffset` | 位偏移（仅 BIT 类型需要） |
| `dataType` | 数据类型：`BIT` / `UINT16` / `FLOAT4` 等 |
| `access` | 读写权限：`RO`（只读） / `RW`（可读可写） |
| `analogConvert` | 是否启用模拟量转换（布尔） |
| `forwardFormula` | 正向公式（PLC 原始值 → 页面显示值），`$a` 占位 |
| `reverseFormula` | 反向公式（页面输入值 → PLC 写入值），`$a` 占位 |
| `defaultValue` | 默认值 |
| `unit` | 单位（与单位字典关联） |
| `description` | 点位说明 |

> 字段集对齐 PRD §2.4 的点表管理项；`analogConvert`、`defaultValue` 等"补充字段"明确建模，避免落到代码里临时判断。

#### 3.4.3 模板使用流程

```
┌──────────────┐    1. 选择设备类型    ┌──────────────┐
│  用户新增设备  │ ───────────────────► │ 模板管理模块  │
└──────────────┘                       └──────┬───────┘
                                              │ 2. 返回模板列表
                                              ▼
                                     ┌──────────────┐
                                     │  前端渲染模板 │
                                     └──────┬───────┘
                                            │ 3. 用户在模板基础上调整点位
                                            ▼
                                     ┌──────────────┐
                                     │ 点表管理模块  │
                                     │ 写入 MongoDB  │
                                     └──────────────┘
```

1. 新增设备时，前端调用模板管理模块获取适用模板列表
2. 用户选定模板后，前端按模板渲染点位表单
3. 用户在模板基础上修改 / 调整后，提交点表管理模块入库
4. 设备上线后，按入库点表进行数据解析与控制

#### 3.4.4 设计约束

- 模板只描述"**默认配置**"，不绑定到具体设备；同一份模板可被多台设备复用
- 模板字段变更需走版本号管理；旧模板继续保留以兼容历史设备
- 模板加载失败时启动失败（fail-fast），避免半状态运行

## 4. 模块调用关系

1. **基础支撑模块为所有业务模块提供底层能力支撑，无业务模块反向依赖**；
2. **点位控制、报警模块依赖点表模块**的权限与规则配置（点表定义了点位读写权限与转换公式）；
3. **报警模块依赖通知人模块与消息通知模块**，实现异常消息推送；
4. **所有业务请求均经过权限模块校验后执行**，权限模块横切所有业务模块；
5. **MQTT 通信模块为设备管理、点位控制、报警管理提供数据通道**，设备上报数据经 MQTT 模块进入业务处理链路；
6. **模板管理模块为点表管理模块提供预置点表**，降低首次配置成本；
7. **审计日志模块横切所有写操作**（配置变更、控制下发、报警确认等）。

### 核心数据流

```
设备上报数据
    │
    ▼
MQTT通信模块（订阅接收 + 共享订阅去重）
    │
    ▼
点表管理模块（匹配点位配置）
    │
    ▼
通用计算模块（正向公式转换）
    │
    ├──► 数据展示模块（实时数据 / 历史数据）
    │
    ├──► 数据持久模块（更新实时点位 + 写入历史）
    │
    └──► 报警管理模块（规则判断 → 触发报警 → 消息通知模块 → 短信/微信推送）
                                              │
                                              ▼
                                         审计日志模块
```

### 控制指令流

```
用户下发控制请求
    │
    ▼
权限管控模块（校验角色 + 校验点位读写权限 + 校验租户）
    │
    ▼
通用计算模块（反向公式转换）
    │
    ▼
MQTT通信模块（发布控制指令至设备）
    │
    ▼
现场 PLC 设备执行
    │
    ▼
审计日志模块（操作记录）
```

### 模板加载流

```
服务启动
    │
    ▼
模板管理模块（扫描 resources/templates/point-table/*.json）
    │
    ├──► 解析失败 → 启动失败（fail-fast）
    │
    └──► 解析成功 → 缓存到内存 + 注册到 Spring 容器
                │
                ▼
         暴露查询接口（按 deviceType 返回模板列表 / 详情）
```
