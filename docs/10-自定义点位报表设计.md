## 3. 名词与边界

### 3.1 术语表

| 术语         | 英文              | 含义                                                                |
|--------------|-------------------|---------------------------------------------------------------------|
| **报表定义** | Report Definition | 一张报表的"查询配方",持久化到 `report_definition.schemaJson`        |
| **报表执行** | Report Execution  | 一次对 Report Definition 的查询,返回结果集(行 + 列)                 |
| **数据源**   | Data Source       | 本期只支持三类:`DEVICE` / `POINT_HISTORY` / `POINT_REALTIME`        |
| **字段**     | Field             | 某个 Data Source 的列名(如 `data_history.doubleValue`)              |
| **列定义**   | Column Definition | 一条输出的逻辑列 = 字段引用 + 可选聚合 + 可选字段间运算             |
| **聚合**     | Aggregation       | `SUM` / `AVG` / `MIN` / `MAX` / `COUNT` / `COUNT_DISTINCT` / `NONE` |
| **运算**     | Operator          | `+` / `-` / `*` / `/`,**仅用于两个列定义之间**                      |
| **分组**     | Breakout          | GROUP BY 一个字段,本期仅支持**单字段**                              |
| **过滤**     | Filter            | 复用现有 `QueriesPageRequest.predicate`(范围 / 等值 / 模糊 / IN 等) |
| **预览**     | Preview           | 编辑时的轻量执行,默认 LIMIT 100,不等正式执行                        |
| **正式执行** | Execute           | 完整执行,默认 LIMIT 5000                                            |

### 3.2 边界:数据来源的"硬约束"

| 数据源           | 实际表             | 可用场景                                          | 时间字段          |
|------------------|--------------------|---------------------------------------------------|-------------------|
| `DEVICE`         | `device`           | 当列 / 当分组                                     | `lastHeartbeatAt` |
| `POINT_HISTORY`  | `data_history`     | 当列 / 当分组 / 当过滤时间字段                    | `ts`(`timestamp`) |
| `POINT_REALTIME` | `data_realtime`    | 当列 / 当分组 / 当过滤时间字段                    | `ts`(`timestamp`) |
| `POINT` (隐含)   | `point_definition` | 仅作"字段名查找辅助",**不能直接出现在 schema 中** | —                 |

## 4. 字段白名单 (写死,不可运行时扩展)

### 4.1 设计原则

- **白名单是报表模块安全的唯一手段**——任何字段拼接到 SQL 前,必须先查到该常量表
- **任何字符串字段名,经过 `ReportFieldWhitelist.resolve(source, field)` 校验,未注册则抛 `bad_request`**
- **字段名变更要走代码评审 + 同步更新本表 + 同步前端下拉选项**

### 4.2 本期字段白名单 (对齐 §1.2.2 项目实体字段)

```text
DEVICE                -> id, deviceName, gatewayId, gatewayType,
                         templateId, enabled, online,
                         level1Tag, level2Tag, level3Tag,
                         lastHeartbeatAt, tenantId
                         (★ tenantId 仅白名单内,但 ReportQueryTranslator 会强制覆盖为当前租户)

POINT                 -> id, deviceId, pointCode, pointName,
                         dataType, access, sortOrder,
                         groupKey, groupLabel, unit, precision
                         (★ POINT 不作为数据源,仅供编辑器做"点位选择器"下拉)

POINT_HISTORY         -> id, deviceId, pointId, pointCode, pointName,

## 5. ReportDefinition 的 JSON Schema(三段式 + 版本号)

### 5.1 顶层结构

```jsonc
{
  "schemaVersion": "1.0",          // ★ 必须字段,字符串;后续版本升级用
  "source": "POINT_HISTORY",       // ★ 单选;枚举见 §5.2
  "joins": [],                      // ★ 数组;本期保留空数组(v2 启用显式 JOIN)
  "columns": [ ... ],               // ★ 数组,≥1,≤20
  "breakout": null,                 // ★ 单字段分组;可为 null(无分组 = 明细)
  "filters": { ... },               // ★ 复用 QueriesPageRequest.predicate 结构
  "limit": 5000                     // ★ 默认 5000,范围 [1, 5000];预览接口强制 100
}
```

### 5.2 `source`(主数据源)

枚举:`"DEVICE"` / `"POINT_HISTORY"` / `"POINT_REALTIME"`

**约定**:

- 必须恰好选 1 个
- 选 `DEVICE` 时,JOIN 自动关联 `POINT_HISTORY` 和 `POINT_REALTIME`(`ON device.id = X.deviceId`)— 这是隐式 JOIN
- 选 `POINT_HISTORY` 时, **不允许** `breakout` 为 `POINT_HISTORY` 之外的字段 (v1 严格,v2 放宽)
- 选 `POINT_REALTIME` 时,同上一条

### 5.3 `joins`(本期始终为空数组)

```jsonc
"joins": [
  // v2 启用,本期 schema 校验直接拒绝非空:
  // {
  //   "source": "POINT_HISTORY",
  //   "alias":  "h",
  //   "on":     [{ "left": {"source": "DEVICE", "field": "id"}, "op": "eq",
  //               "right": {"source": "POINT_HISTORY", "field": "deviceId"} }]
  // }
]
```

> **本期隐式 JOIN 规则**(写死,翻译器内置):
> - `source = DEVICE` 时,自动 LEFT JOIN `data_history h ON h.device_id = device.id`
> - `source = DEVICE` 时,自动 LEFT JOIN `data_realtime r ON r.device_id = device.id`
> - `source = POINT_HISTORY` 时, **不再**额外 JOIN
> - `source = POINT_REALTIME` 时, **不再**额外 JOIN

### 5.4 `columns`(列定义数组)

每条列结构:

```jsonc
{
  "alias":     "avgTemp",       // ★ 输出列名;正则 ^[A-Za-z_][A-Za-z0-9_]{0,63}$;唯一
  "source":    "POINT_HISTORY", // ★ 引用的数据源
  "field":     "doubleValue",   // ★ 数据源下的字段名,必须在 §4 白名单中
  "agg":       "AVG",           // ★ 见 §5.5;默认 "NONE"
  "format":    "decimal2",      // ★ 见 §5.6;默认 "raw"
  "op":        null,            // ★ 见 §5.7;默认 null
  "operand":   null             // ★ 当 op != null 时,必须填写,见 §5.7
}
```

**约束**:

1. `alias` 在同一 schema 中 **唯一**;正则校验
2. `source` + `field` 必须能从 §4 白名单解析到具体列
3. 当 `agg = NONE` 时,该列 = 明细级别
4. 当 `agg ∈ {SUM, AVG, MIN, MAX, COUNT, COUNT_DISTINCT}` 时,该列 = 聚合级别
5. `op` 与 `operand` 必须同时出现或同时为 null
6. 列数:1 ≤ N ≤ 20

### 5.5 `agg`(聚合枚举)

| 值               | 翻译                          | 备注                                              |
|------------------|-------------------------------|---------------------------------------------------|
| `NONE`           | 不加聚合函数,直接 SELECT 字段 | 明细行;若同时 `breakout != null`,报 `bad_request` |
| `SUM`            | `SUM(field)`                  | 仅数值字段可聚合                                  |
| `AVG`            | `AVG(field)`                  | 同上                                              |
| `MIN`            | `MIN(field)`                  |                                                   |
| `MAX`            | `MAX(field)`                  |                                                   |
| `COUNT`          | `COUNT(field)`                | COUNT(*) 由 `COUNT_DISTINCT` + `id` 表达          |
| `COUNT_DISTINCT` | `COUNT(DISTINCT field)`       |                                                   |

**校验约束**:

- `SUM` / `AVG` / `MIN` / `MAX`:字段必须属于 `INT` / `DOUBLE` 类型族
- `COUNT`:任意字段
- `COUNT_DISTINCT`:任意字段
- `NONE` + `breakout = null`:合法 (纯明细)
- `NONE` + `breakout != null`:**非法**(无聚合却分组,SQL 报错)

### 5.6 `format`(显示格式)

| 值         | 含义                          | 后端处理                   |
|------------|-------------------------------|----------------------------|
| `raw`      | 原样返回                      | 直接                       |
| `decimal2` | 保留 2 位小数                 | `String.format("%.2f", v)` |
| `decimal4` | 保留 4 位小数                 | 同上                       |
| `percent2` | 百分比(×100 + 2 位小数 + `%`) | `(v * 100).formatted(...)` |
| `int`      | 转 Long                       | 仅整型字段                 |
| `string`   | 转 String                     | 仅数值字段,反序列化展示用  |

**`format` 只影响"返回值",不影响 SQL**,后端在结果转换时统一处理。

### 5.7 `op` + `operand`(字段间运算)

#### 5.7.1 语法

```jsonc
{
  "alias":    "diff",
  "source":   "POINT_HISTORY",
  "field":    "doubleValue",   // ★ "左操作数"
  "agg":      "MAX",
  "op":       "SUB",           // ★ 运算符
  "operand":  {                 // ★ "右操作数"
    "source": "POINT_HISTORY",
    "field":  "doubleValue",
    "agg":    "MIN"             // operand 自身也可指定聚合
  },
  "format":   "decimal2"
}
```

语义:**`MAX(doubleValue) - MIN(doubleValue)`**,意为同一组内 max-min 极差。

#### 5.7.2 运算符枚举

| `op` 值 | SQL        | 约束                                                      |
|---------|------------|-----------------------------------------------------------|
| `null`  | 不加运算符 | operand 必须为 null                                       |
| `ADD`   | `+`        | 左右操作数都必须是数值                                    |
| `SUB`   | `-`        | 同上                                                      |
| `MUL`   | `*`        | 同上                                                      |
| `DIV`   | `/`        | 同上,且除数表达式不能为 0(运行时 SQL 抛错,前端兜底显示空) |

#### 5.7.3 操作数 (operand)结构

```jsonc
{
  "source": "POINT_HISTORY",
  "field":  "doubleValue",
  "agg":    "NONE" | "SUM" | ...
}
```

**operand 不支持再嵌套 `op/operand`**—— **只允许 1 层运算**。

#### 5.7.4 运算层级的合法性矩阵 (重要)

| 左 agg | 右 agg | 是否合法        | 翻译                       |
|--------|--------|-----------------|----------------------------|
| `NONE` | `NONE` | ✅ 明细级别运算 | `(left - right)`           |
| `AGG`  | `AGG`  | ✅ 聚合级别运算 | `(AGG(left) - AGG(right))` |
| `NONE` | `AGG`  | ❌ 非法         | 抛 `bad_request`           |
| `AGG`  | `NONE` | ❌ 非法         | 抛 `bad_request`           |

**理由**:

- `NONE + AGG` 在同一 SELECT 里无意义,要么全聚合要么全明细
- 强制对齐后,翻译逻辑简单且语义清晰

## 6. 安全与隔离(本期最关键章节)

### 6.1 攻击面分析

| 攻击面 | 防御 |
|---|---|
| 用户提交 `field` = `"; DROP TABLE..."` | §4 白名单常量,**任何未声明字段直接 400** |
| 用户提交 `source` = 任意字符串 | §5.2 枚举校验 |
| 用户提交 `agg` = 任意字符串 | §5.5 枚举校验 |
| 用户提交 `op` = `"||"` / `"OR 1=1"` | §5.7.2 枚举校验 |
| 用户提交 `alias` = 注入到响应 JSON 的恶意字段 | §5.4 正则 + 前端不解析 `alias` 为 React 节点 |
| 用户提交 `schemaJson` = 巨大 JSON | 服务端 `@Size(max = 65536)` 校验 |
| 用户提交 `schemaVersion` = 不支持版本 | §10.1 版本兼容表 |

### 6.2 翻译器是"受信代码"

`ReportQueryTranslator` 是**纯受信模块**,接收 `ReportSchema`(已通过校验的对象),产出 JPA `CriteriaQuery`。

**关键纪律**:
- **翻译器内部不允许再调一次"字符串拼 SQL"**——只能用 `CriteriaBuilder` / `Path` / `Expression<?>`
- **翻译器内部不允许反射访问实体**——只能走白名单常量
- **任何想"绕过白名单"的需求,必须先扩白名单,再走代码评审**

### 6.3 显式不允许的查询模式

| 模式 | 是否允许 | 错误 |
|---|---|---|
| `source = POINT` | ❌ | `unsupported_source: POINT 不能作为数据源` |
| `joins` 非空数组 | ❌ | `unsupported_joins: 本期不支持显式 JOIN` |
| `breakout` 多字段 | ❌ | `breakout_must_be_single_field` |
| `columns` 中 `agg=NONE` 但 `breakout != null` | ❌ | `mixed_agg_level_in_breakout` |
| `columns` 中 `op` 不为 null 但 `operand = null` | ❌ | `operand_required_when_op_present` |
| `agg = SUM` 但字段是 `STRING` | ❌ | `agg_not_applicable_to_field_type` |
| `schemaVersion` 不在白名单 | ❌ | `unsupported_schema_version` |
| `limit > 5000` | ❌ | `limit_exceeded` |
| `alias` 不符合正则 | ❌ | `invalid_alias` |
| `alias` 重复 | ❌ | `duplicate_alias` |
| `columns` 数组为空或 > 20 | ❌ | `columns_out_of_range` |

### 6.4 为什么 POINT 不能作为数据源?

`point_definition` 是**元数据表**(点位编码 + 单位 + 类型),不是数据本身。报表需要的是**值**——点位历史表/实时表才有值。

如果用户想做"每个点位最近一次上报的当前值"——他应该选 `POINT_REALTIME` + `breakout = pointCode` 而不是 `POINT`。

如果将来需要,可在 `columns.field` 的允许值里引入 `POINT.xxx`,但**不**让 `POINT` 整体作为 root。

### 6.5 租户隔离的完整链路

> 本项目已 90% 基础设施到位(`TenantBaseEntity` + `UserContext.tenantId()` + `withTenantFilter()`),报表模块只需要补最后 10%。

#### 6.5.1 配置层(`report_definition` 表)

| 操作 | 隔离机制 |
|---|---|
| **查询列表** | `req.withTenantFilter()` 自动追加 `tenantId = :currentTenant`(`"0"` 除外) |
| **保存/更新** | `ReportService.save` 内显式校验 `exist.tenantId == currentTenant`;**新建时** `stampCreated` 自动写 `tenantId` |
| **删除** | 同上 + `markDeleted` 不改变 `tenantId` |
| **按 ID 获取** | 走 `findById` 后显式校验 `tenantId`,**不一致抛 `not_found`**(隐藏存在性) |

#### 6.5.2 执行层(报表查询)

**`ReportQueryTranslator` 必须对每个 root / 每个 join 都加 `tenantId` 条件**:

```text
若 source = DEVICE        → root = DeviceEntity,     + tenantId 过滤
                              LEFT JOIN history       → join,    + tenantId 过滤
                              LEFT JOIN realtime      → join,    + tenantId 过滤
若 source = POINT_HISTORY → root = DataEntity,       + tenantId 过滤
若 source = POINT_REALTIME→ root = RealtimeDataEntity,+ tenantId 过滤
```

**实现关键**:

```java
String currentTenant = UserContext.tenantId()
    .orElseThrow(() -> new UnauthorizedException("未识别租户"));
// DEFAULT_TENANT_ID("0") 也走过滤:WHERE tenant_id = '0'  → 看不到真租户数据
```

#### 6.5.3 租户值的特殊性

| 当前用户                                                              | `UserContext.tenantId()` 返回    | 行为                     |
|-----------------------------------------------------------------------|----------------------------------|--------------------------|
| 普通 ADMIN                                                            | `"tnt_abc123"`                   | 只能看本租户数据         |
| OPERATOR                                                              | `"tnt_abc123"`                   | 同上                     |
| SUPER_ADMIN                                                           | `"tnt_abc123"`(当前会话所在租户) | 看本租户数据             |
| SUPER_ADMIN 切换到 `"0"`(用 `loginType=REFRESH + targetTenantId="0"`) | `"0"`                            | 看所有租户数据(超管视角) |
| 系统任务(seed/test)                                                   | `"0"`(默认)                      | 看所有租户数据           |

实现:`@PreAuthorize("hasAnyRole('SUPER_ADMIN','ADMIN')")` +
`@PreAuthorize("hasAnyRole('SUPER_ADMIN','ADMIN','OPERATOR')")`

- `markDeleted`(state = -1),不真删
- 软删后,`query` API 通过 `withTenantFilter()` + `JpaQueriesExecutor` 默认只查 `state=0`—— **需确认 JpaQueriesExecutor
  已默认过滤 state**(如未默认,在 Service 内补一道)

- `1.0`:本期唯一
- 升级时:旧版本 schema 在加载时跑 `ReportSchemaMigrator.migrate(json, fromVersion)`,失败则不允许加载

## 15. FAQ

**Q1:为什么不允许 `POINT` 作为 source?**
A:见 §6.4。`point_definition` 是元数据表,本身不含"值",数据在 `data_history` / `data_realtime`。

**Q2:为什么 `agg=NONE + breakout != null` 非法?**
A:SQL 语义:`SELECT field FROM t GROUP BY x` 中,SELECT 列表只能是"分组键"或"聚合函数",不能是其他字段。这是数据库约束,不是设计选择。

**Q3:为什么限制 GROUP BY 单字段?**
A:用户原话明确说"允许 group by 一个字段",且单字段版本翻译器实现极简,v2 放开到多字段几乎零成本(只改 `breakout` 类型为数组 + 校验)。

**Q4:为什么 `operand` 不支持嵌套运算?**
A:`(A + B) * C` 这种嵌套本期不做,会大幅膨胀翻译器;若需要 v2 可改 `operand` 为递归 `ColumnDef`,但 schema 会变得复杂。

**Q5:为什么 `alias` 用正则严格校验?**
A:`alias` 会出现在响应 JSON 的 key 上,如果允许 `__proto__` / `constructor` 等字符串,某些前端库(JSON.parse 完直接 `result.alias` 访问)有原型链污染风险。

**Q6:`SUPER_ADMIN` 切到 `tenantId="0"` 后,看的是"系统租户"还是"全部租户"?**
A:看全部。系统租户 `"0"` 的 `tenantId="0"` 也会被过滤(只有真实租户数据被 `stampCreated` 写入,默认租户下没有业务数据)。

**Q7:能不能做"在多个点位编码上同时聚合"?**
A:本期不支持。多点位 = 多行结果;若需"横向聚合",应使用 `data_history` 直接 JOIN `point_definition`,但本期隐式 JOIN 不支持——v2 显式 JOIN 启用后可做。

**Q8:报表能引用另一个报表吗?**
A:不能。本期 schema 是叶子节点,无 `source.schema` 引用。

**Q9:`enabled = false` 的报表定义能否被 SUPER_ADMIN 执行?**
A:不能。`enabled = false` 等同于"停用",任何角色都不能执行(执行前翻译器先查 `enabled`,失败抛 `not_found`)。

**Q10:报表模块的审计?**
A:本期不新增审计表,复用 `BaseEntity.createId/updateId`(已由基类写入)。后续如需"谁执行了什么报表",v2 加 `report_execution_log` 表。

### 2.3 不学 Metabase 的 5 个地方

| # | 不学 | 原因 |
|---|---|---|
| A1 | **不学通用表达式引擎**(S-expression) | 维护成本高(见上轮讨论);用 record 描述单层运算即可 |
| A2 | **不学数据反射 / 自动发现字段** | 字段白名单**写死常量**,运行时不动 schema |

| A4 | **不学字段 ID 元数据表**(`metabase_field`) | 用字段名字符串 + 重命名兜底校验 |
| A5 | **不学 SQL 反向解析**(native → MBQL) | 单向编译,够用 |
