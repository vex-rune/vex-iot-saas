# 项目工作量与进度评估

> 评估日期：2026-08-27
>
> 评估基准：1 名全栈开发 + AI 辅助编码（Trae / Cursor 类工具）
>
> 项目范围：工业 IoT 设备监控运维平台 MVP（接入 → 配置 → 采集 → 监控 → 控制 → 报警 → 通知 → 部署上线）

---

## 一、评估前提

| 项 | 说明 |
|---|---|
| 人员配置 | 1 名全栈开发 |
| 开发方式 | AI 辅助编码，CRUD 类代码由 AI 生成，人工负责架构决策与联调 |
| 站点情况 | 80 个站点，仅 4 种设备类型，同类型仅名称/编号不同，点表可模板复用 |
| 交付标准 | MVP 核心链路可用并上线；报表导出、可视化看板、微信通知、配置回滚等列入二期 |
| 已有基础 | 后端骨架（domain + service + ops）已搭建，3 套点表模板已就绪，仅需补 1 套 |
| 工作日口径 | 每周 5 个工作日，1 个月 ≈ 20–22 个工作日 |

## 六、风险与说明

| 风险 | 影响 | 应对 |
|---|---|---|
| 现场寄存器表不准确 | 点表配置需返工 | 先做 1–2 个试点站验证模板，再批量铺开 |
| MQTT 公网通信不稳定 | 数据上报中断 | 网关侧本地缓存 + 断线重连 |
| AI 生成代码有隐含 bug | 联调阶段集中暴露 | 每个模块完成后立即自测，不留到最后统一联调 |
| 单人开发无交叉验证 | 架构决策风险 | 关键设计点先对齐方案再动手 |

---

> 本评估基于 AI 辅助开发模式，CRUD 类代码由 AI 生成、人工审查；复杂业务逻辑（报警引擎、公式转换、时序查询）以人工为主、AI 辅助。实际进度取决于现场设备配合度与联调顺利程度。
