## 技术栈总览

- **后端**：Java 17 + Spring Boot 3.x + Spring Security + JWT
- **前端**：React 18 + TypeScript + Vite + Ant Design 5
- **数据库**：MongoDB（业务数据 + 3个月热时序数据，按月分集合）
- **冷存储**：OSS 对象存储（超3个月历史数据快照压缩归档）
- **通信**：MQTT（EMQX 5.8 Broker）
- **部署**：Nginx 负载均衡 + SpringBoot 双实例无状态部署
- **通知**：短信 + 微信（公众号/企业微信）

## 数据存储策略

- **存储模型**：按设备存 500 字节原始数据包（BinData），不按点位拆分；点位值由应用层按指针偏移从原始包解析
- **热数据**：近 3 个月设备历史数据存 MongoDB，30秒/条/设备，复合索引 `(deviceId, timestamp)`
- **冷数据**：超 3 个月数据由定时任务每月归档，gzip 压缩后上传 OSS，删除 Mongo 对应集合
- **数据量**：80设备 × 30秒/条 = 23万条/天，691万条/月，3个月约2074万条，磁盘约 10-15 GB
- **死区过滤**：设备数据无变化不存，可减少 30%-70% 数据量
- **建议云盘**：100 GB 起步

## 核心业务模块

1. 设备管理
2. 点表管理
3. 点位监控与控制
4. 通知人设置
5. 报警设置

## 角色权限

- **管理员**：全部功能操作权限，负责系统配置、设备管理、参数配置、人员配置、规则配置
- **操作人员**：仅设备查看、点位监控、合法点位远程控制，无任何配置/新增/删除权限
