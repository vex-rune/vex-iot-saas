# USR-G771 MQTT 边缘计算：JSON 组包上报与写数据

> 适用范围：USR-G771 轻边缘（固件 VER: V2.4.01.000000.0000 及以上支持 Modbus 轮询）
>
> 参考资料：
> - 轻边缘连接 MQTT 服务器 Json 组包上报：<https://www.usr.cn/wiki/puba/g9dB2cAOS>
> - 轻边缘版连接 MQTT 服务器 Json 写数据：<https://www.usr.cn/wiki/puba/OqFLNcDwF>
> - 轻边缘连接 MQTT 服务器 GNSS 和 Json 组包上报：<https://www.usr.cn/wiki/puba/iJVIAqQL1>
> - 母文档：[边缘网关_USR-G771.md](./边缘网关_USR-G771.md)

USR-G771 通过"轻边缘"固件 + Modbus 轮询 + JSON 组包上报，实现"网关按周期主动采从机寄存器 → 以 JSON 推送到 MQTT 服务器"的能力；服务端再通过另一个主题下发 JSON 命令，即可向从机寄存器写入数据。

---

## 一、总体流程

```
                     ┌────────────────────────────────┐
                     │  MQTT 服务器 (broker.emqx.io)  │
                     └──────────────┬─────────────────┘
                                    │
        Publish topic: /USR-G771/update  │  Subscribe topic: /USR-G771/get
                                    │
                     ┌──────────────┴─────────────────┐
                     │  USR-G771 轻边缘网关 (4G Cat-1) │
                     │  工作模式: MQTT 透传             │
                     │  轮询上报方式: JSON 组包上报      │
                     └──────────────┬─────────────────┘
                                    │ RS-485 / RS-232 (Modbus RTU)
                     ┌──────────────┴─────────────────┐
                     │  Modbus 从机（PLC / 仪表 / 模拟）│
                     └────────────────────────────────┘
```

| 方向 | MQTT Topic | 方向码 | 内容 |
| --- | --- | --- | --- |
| 网关 → 云 | `/USR-G771/update` | `dir: up` | JSON 组包上报（读寄存器结果） |
| 云 → 网关 | `/USR-G771/get`    | `dir: down` | JSON 下发写寄存器命令 |

## 二、必须完成的配置项

### 2.1 硬件连接

| 项目 | 说明 |
| --- | --- |
| 串口 | USR-G771 的 **485 串口**（或 GNSS 场景用 232 串口）经 USB 转 RS485/RS232 串口线连 PC |
| 电源 | 12V 电源适配器上电 |
| 4G | 装好 SIM 卡、接好 4G 天线 |
| PC 端工具 | 轻边缘设置软件、MQTT.fx、Modbus Slave（用于模拟从机） |

### 2.2 设置软件通道一参数（MQTT 模式）

| 配置项 | 取值 |
| --- | --- |
| 启用通道一 | 勾选 |
| 工作模式 | **MQTT 模式** |
| MQTTClient 连接 | **通用 MQTT** |
| 服务器地址 | 目标 MQTT Broker（例：`broker.emqx.io`） |
| 端口 | `1883`（TLS 用 8883） |
| 用户名 / 密码 | 按 Broker 要求填写，无则留空 |
| 客户端 ID | 自定义，**不能与 MQTT.fx 等其他客户端重复**（例：`1234567890`） |
| MQTT 串口传输模式 | **透传模式** |
| 订阅主题 | 勾选主题 1，填 `/USR-G771/get`（云下发的写命令） |
| 推送主题 | 勾选主题 1，填 `/USR-G771/update`（网关上报数据） |

> 配置完成后点击「设置并保存所有参数」。

### 2.3 Modbus 轮询采集参数（核心）

| 配置项 | 取值 |
| --- | --- |
| 启动 Modbus 轮询 | 勾选 |
| 轮询上报方式 | **JSON 组包上报** |
| 变量配置 | 按"变量名 / 从机地址 / 功能码 / 寄存器地址 / 数据类型 / 倍率 / 上报方式"添加点位 |
| 变量名 | 自定义（例：`data1`、`data2`），**JSON 写数据时 r_data / w_data 中的 name 必须与此一致** |

> 从机寄存器地址、数据类型必须与 Modbus 从机实际配置保持一致。

### 2.4 MQTT.fx（或其他客户端）参数

| 配置项 | 取值 |
| --- | --- |
| 配置文件名 | 自定义（例：`MQTT`） |
| 服务器地址 / 端口 | 与 G771 一致（`broker.emqx.io` / `1883`） |
| Client ID | 另起一个，**不能与 G771 相同** |
| User Credentials | 按 Broker 要求填写，可空 |
| 操作 | 点 `Connect` 连接；点 `Subscribe` 订阅 `/USR-G771/update` 接收上报；点 `Publish` 向 `/USR-G771/get` 下发写命令 |

### 2.5 Modbus Slave（从机模拟，可选）

| 配置项 | 取值 |
| --- | --- |
| Slave ID | 1 |
| Function | 03（保持寄存器） |
| Address | 起始 0 |
| Quantity | 与变量数一致 |
| Connection | 选 G771 所接 USB 串口 COM 号 |
| Mode | RTU（模拟 Modbus RTU） |

## 三、上报：MQTT 收到的消息格式

### 3.1 完整报文示例

订阅主题 `/USR-G771/update`，网关按轮询周期推送如下 JSON：

```json
{
  "params": {
    "dir": "up",
    "id": "00601924061200038538",
    "r_data": [
      { "name": "data1", "value": "10",  "err": "0" },
      { "name": "data2", "value": "20",  "err": "0" },
      { "name": "data3", "value": "30",  "err": "0" }
    ]
  }
}
```

### 3.2 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `params.dir` | 是 | 方向，**上报固定为 `up`** |
| `params.id`  | 是 | 设备唯一标识（与设置软件中的客户端 ID / SN 对应，本例为 SN `00601924061200038538`） |
| `params.r_data` | 是 | 读上来的变量数组，每轮询周期上报一次 |
| `r_data[].name`  | 是 | 变量名，与"Modbus 轮询采集点位配置"中定义的变量名一一对应 |
| `r_data[].value` | 是 | 寄存器当前值，**统一为字符串**（即使 16 位无符号也会带引号） |
| `r_data[].err`   | 是 | 读取错误码：`0` = 成功；非 0 = 异常 |

### 3.3 关键约束

- **变量名必须与设置软件配置一致**（例如：设置里变量叫 `data1`，上报里 `r_data[].name` 就是 `data1`）。
- 上报时机：网关按 Modbus 轮询周期主动推送，而非"有变化才推"。
- `value` 始终是 JSON 字符串，解析时需按字符串处理再按需转换为数值。

## 四、写数据：MQTT 下发 JSON 命令格式

### 4.1 完整报文示例

向主题 `/USR-G771/get` 发布以下 JSON 即可写从机寄存器：

```json
{
  "rw_prot": {
    "Ver": "1.0.1",
    "dir": "down",
    "id": "00601924061200038538",
    "r_data": [
      { "name": "data1" },
      { "name": "data2" },
      { "name": "data3" }
    ],
    "w_data": [
      { "name": "data1", "value": "100" },
      { "name": "data2", "value": "200" },
      { "name": "data3", "value": "300" }
    ]
  }
}
```

### 4.2 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `rw_prot.Ver` | 是 | 协议版本号，固定 `"1.0.1"` |
| `rw_prot.dir` | 是 | 方向，**下发固定为 `down`** |
| `rw_prot.id`  | 是 | 目标设备 ID（与上报 `params.id` 一致；网关据此判定命令是否发给自己） |
| `rw_prot.r_data` | 是 | 需要"读完再回写"的变量列表（仅写时一般只需 `name`） |
| `rw_prot.w_data` | 是 | 要写入的目标变量与值 |
| `w_data[].name`  | 是 | 变量名，**必须与"Modbus 轮询采集点位配置"中定义的变量名一致** |
| `w_data[].value` | 是 | 写入值，统一为 JSON 字符串 |

### 4.3 行为说明

1. 网关收到 `/USR-G771/get` 的 JSON 命令后，按 `w_data` 向 Modbus 从机写寄存器。
2. 写操作完成后，网关会**立即按轮询周期重新采集一次**，并通过 `/USR-G771/update` 上报新值，格式与第三节日报一致。
3. 写后再次上报的示例：

```json
{
  "params": {
    "dir": "up",
    "id": "00601924061200038538",
    "r_data": [
      { "name": "data1", "value": "100", "err": "0" },
      { "name": "data2", "value": "200", "err": "0" },
      { "name": "data3", "value": "300", "err": "0" }
    ]
  }
}
```

### 4.4 关键约束

- `r_data` 与 `w_data` 中 `name` 必须严格匹配设置软件里配置的变量名，否则写失败。
- `value` 字段必须用 JSON 字符串，**不要写成数字**（如 `"100"` 而非 `100`）。
- `id` 必须填目标 G771 的设备标识，否则网关会忽略该命令。

## 五、排障清单

| 现象 | 排查项 |
| --- | --- |
| MQTT.fx 收不到上报 | 1) 订阅主题是否填写 `/USR-G771/update`；2) G771 是否已连接 Broker（看 LINK 灯）；3) 客户端 ID 是否冲突 |
| 下发写命令无响应 | 1) 发布主题是否填写 `/USR-G771/get`；2) JSON 字段是否完整（`Ver` / `dir` / `id` / `r_data` / `w_data`）；3) `name` 是否与设置软件一致；4) `value` 是否带引号 |
| 上报 `err` 非 0 | Modbus 通讯异常，检查从机地址、寄存器地址、串口参数、485 接线（A/B 是否反接） |
| 变量值不对 | 数据类型/倍率配置错误；16 位有符号 vs 无符号差异 |
